# 数据分析岗位全景手册（SQL 之外）

写给零基础转行者：把除 SQL 以外，数据分析岗位需要的概念、知识、工具、思维和求职要点列成一张查询地图。

**频率说明：** ★★★ 必会，几乎所有岗位都要　★★ 建议掌握，常见于面试和工作　★ 了解即可，遇到再查。

**先说明两点：** 一，不同公司、不同岗位的要求差别很大，最终以招聘要求（JD）为准；二，这份手册是「知道有什么」，不是要求一次学完，学习顺序见最后一节。

## 0. 岗位全景

数据分析师的日常工作链条：**明确问题 → 取数 → 清洗 → 分析 → 可视化 → 结论与建议 → 推动落地、复盘**。SQL 主要负责「取数」这一环，其余环节同样关键。

| 岗位方向 | 主要工作 | 技能侧重 |
| --- | --- | --- |
| 业务 / 运营数据分析 | 支持运营决策，做看板、专题分析、活动复盘 | SQL、Excel、BI、业务理解 |
| 产品数据分析 | 分析用户行为、功能效果，做 A/B 测试 | SQL、统计、埋点、实验设计 |
| 商业分析（BA） | 市场、经营、成本相关分析 | Excel、PPT、财务与业务理解 |
| BI / 报表分析 | 搭建指标体系、报表、看板 | SQL、BI 工具、数仓基础 |
| 数据挖掘 / 算法 | 建模、预测、推荐 | Python、机器学习、统计，门槛明显更高 |

**能力模型：** 工具技能 + 统计知识 + 业务理解 + 分析思维 + 沟通表达。五项里，新人最容易只练工具，而面试和工作中拉开差距的往往是后三项。

## 1. 核心指标与业务概念

这是门外汉最容易漏掉的一块：很多概念没人教，但面试和日常工作里会默认你懂。

| 概念 | 含义 / 公式 | 频率 |
| --- | --- | --- |
| 同比 | （本期 − 去年同期）÷ 去年同期，用于排除季节性影响 | ★★★ |
| 环比 | （本期 − 上期）÷ 上期，看短期变化；受节假日影响大 | ★★★ |
| 定基比 | 都与某个固定基期相比 | ★ |
| 增长率 / 增量 | 变化的比例 / 绝对变化量，要结合看，基数小时增长率会虚高 | ★★★ |
| CAGR 复合增长率 | （期末 ÷ 期初）^(1 ÷ 年数) − 1 | ★ |
| 占比 / 结构 | 部分 ÷ 整体，看构成变化 | ★★★ |
| 转化率 | 完成目标的人数 ÷ 进入环节的人数 | ★★★ |
| 漏斗 | 把流程拆成多步，看每一步的流失 | ★★★ |
| 留存率 | 第 N 天仍活跃的用户 ÷ 当天新增用户（次日、7 日、30 日） | ★★★ |
| 流失率 | 某周期内流失用户 ÷ 期初用户，与留存相对 | ★★ |
| DAU / WAU / MAU | 日 / 周 / 月活跃用户数；DAU ÷ MAU 反映粘性 | ★★★ |
| PV / UV | 页面浏览量 / 独立访客数 | ★★★ |
| 新增、活跃、沉默、回流 | 用户生命周期的不同状态 | ★★ |
| 付费率 | 付费用户 ÷ 活跃用户 | ★★ |
| 客单价 | 成交金额 ÷ 成交用户数（或订单数，要写清口径） | ★★★ |
| ARPU / ARPPU | 人均收入（按活跃用户 / 付费用户计算） | ★★ |
| GMV | 成交总额，含未支付或退款部分，与实际收入不同 | ★★★ |
| 复购率 | 购买两次及以上的用户 ÷ 购买用户 | ★★★ |
| LTV | 用户生命周期内的总价值 | ★★ |
| CAC | 获取一个用户的成本 | ★★ |
| ROI / ROAS | 投入产出比 / 广告花费回报 | ★★ |
| CTR / CVR | 点击率 / 转化率（广告、推荐常用） | ★★ |
| 跳出率 | 只访问一个页面就离开的比例 | ★★ |
| 毛利率 | （收入 − 成本）÷ 收入 | ★★ |
| 渗透率 | 使用某功能或产品的用户 ÷ 目标用户 | ★★ |
| NPS | 净推荐值，衡量用户满意度 | ★ |
| 北极星指标 | 最能代表产品核心价值的那一个指标 | ★★ |
| 指标口径 | 指标的统计规则（时间范围、去重方式、包含范围） | ★★★ |

**最重要的一条：指标口径。** 同一个「活跃用户」，A 部门按登录算，B 部门按有行为算，数字就对不上。分析前先确认口径，是新人最常见的坑，也是面试高频考点。

## 2. 基础统计学

不用学到数学专业的深度，但要能读懂、能判断数字是否可信。

| 概念 | 通俗解释 | 频率 |
| --- | --- | --- |
| 均值、中位数、众数 | 三种「中间水平」；有极端值时中位数更稳健（如收入） | ★★★ |
| 方差、标准差 | 数据的波动程度 | ★★★ |
| 极差、四分位数、IQR | 最大减最小；25%、50%、75% 位置的值；IQR 常用来判断异常值 | ★★ |
| 百分位数（P90、P99） | 排在某个位置的值，用于看响应时间、收入分布 | ★★ |
| 分布 | 数据的形状：正态分布、偏态、长尾 | ★★★ |
| 箱线图、直方图 | 用来看分布和异常值 | ★★ |
| 异常值 | 明显偏离整体的值；先判断是错误还是真实情况，再决定删除、保留或单独分析 | ★★★ |
| 相关系数 | 衡量两个变量一起变化的程度（−1 到 1） | ★★★ |
| 相关 ≠ 因果 | 一起变化不代表一个导致另一个，可能有第三个因素 | ★★★ |
| 总体与样本 | 全部对象 / 抽出来研究的部分；样本要有代表性 | ★★★ |
| 抽样方法 | 简单随机、分层、整群、系统抽样 | ★★ |
| 选择偏差、幸存者偏差 | 只看到被选中或活下来的样本，结论会失真 | ★★★ |
| 置信区间 | 估计值可能的范围，区间越窄越精确 | ★★ |
| 假设检验 | 先假设「没有差异」，用数据判断这个假设是否站得住脚 | ★★★ |
| p 值 | 在「没有差异」成立的前提下，出现当前结果或更极端结果的概率；常用 0.05 作门槛 | ★★★ |
| 显著性水平 α | 事先设定的容忍误判概率 | ★★ |
| 第一类 / 第二类错误 | 误判有差异 / 漏判真实差异 | ★★ |
| 统计功效 | 真有差异时能检测出来的概率 | ★★ |
| t 检验、卡方检验 | 比较两组均值 / 比较比例或分类数据 | ★★ |
| 样本量 | 样本太小结论不稳，需要事先估算 | ★★★ |
| 中心极限定理 | 样本均值近似正态，是很多检验的理论基础 | ★ |
| 线性回归、R² | 用变量预测结果，R² 衡量拟合程度 | ★★ |
| 辛普森悖论 | 分组看与合并看结论相反，分析时必须按维度拆开看 | ★★★ |
| 标准化 / 归一化 | 把数据缩放到可比较的范围 | ★ |
| 贝叶斯思想 | 用新证据更新原有判断 | ★ |

## 3. A/B 测试

产品和运营类岗位的高频考点。基本逻辑：把用户随机分成两组，一组用旧方案（对照组），一组用新方案（实验组），比较关键指标的差异是否可靠。

**标准流程：**

1. 提出假设，如「缩短注册流程会提高注册转化率」。
2. 确定指标：一个核心指标，加若干护栏指标（防止此消彼长，如转化上升但退款率也上升）。
3. 随机分流，保证两组用户特征相近。
4. 估算样本量与实验周期（至少覆盖完整的一周，消除星期效应）。
5. 运行实验，期间不提前偷看结果就下结论。
6. 做显著性检验，同时看效果大小是否有业务价值。
7. 得出结论：上线、不上线，还是继续迭代。

| 概念 | 说明 | 频率 |
| --- | --- | --- |
| 对照组 / 实验组 | 用旧方案 / 新方案的两组用户 | ★★★ |
| 随机化 | 保证两组可比，是实验可信的前提 | ★★★ |
| 核心指标与护栏指标 | 衡量成败 / 防止副作用 | ★★★ |
| 显著性、p 值 | 差异是否大概率不是随机波动 | ★★★ |
| 样本量与功效 | 样本太少，真实差异也测不出来 | ★★ |
| MDE（最小可检测效应） | 实验能识别的最小变化幅度 | ★ |
| 实验周期 | 过短受星期效应、新奇效应影响 | ★★ |
| 新奇效应 / 首因效应 | 用户对新功能先好奇、后回落，或先排斥、后适应 | ★★ |
| 多重比较问题 | 同时看很多指标，总会碰到偶然显著，要谨慎 | ★★ |
| 偷看（Peeking） | 中途频繁检查并提前停止，会提高误判概率 | ★★ |
| SRM（样本比例异常） | 两组人数比例与预设不符，说明分流有问题 | ★ |
| 无法做 A/B 的替代方法 | 前后对比、双重差分（DID）、倾向得分匹配 | ★ |

**面试常见问法：** 设计一个 A/B 测试评估某个功能；实验组指标显著提升但没上线的原因；如何判断样本量够不够。

## 4. 分析方法与思维框架

**常用分析方法**

| 方法 | 做什么 | 典型场景 | 频率 |
| --- | --- | --- | --- |
| 对比分析 | 与历史、目标、同类对象比较 | 同比环比、达成率、A 组对 B 组 | ★★★ |
| 趋势分析 | 看指标随时间的变化 | 日活走势、销售季节性 | ★★★ |
| 细分 / 维度拆解 | 按渠道、地区、用户类型拆开，找变化来自哪里 | 指标异动定位 | ★★★ |
| 结构 / 占比分析 | 看构成及其变化 | 品类销售结构 | ★★★ |
| 漏斗分析 | 看多步流程每步的流失 | 注册、下单流程 | ★★★ |
| 留存分析 / 同期群（Cohort） | 按新增时间分批，追踪各批用户的留存 | 评估产品改版的长期影响 | ★★★ |
| 用户分层 / RFM | 按最近消费、频次、金额分档 | 精细化运营 | ★★ |
| 帕累托分析（80/20） | 找出贡献大部分结果的少数对象 | 重点客户、爆款商品 | ★★ |
| 相关分析 | 看变量之间的关联 | 找影响销量的因素 | ★★ |
| 归因分析 | 判断各渠道或触点的贡献 | 投放效果评估 | ★★ |
| 回归分析 | 量化多个因素对结果的影响 | 价格与销量关系 | ★ |
| 聚类 | 无标签地把用户分群 | 用户画像 | ★ |
| 预测 | 基于历史预测未来 | 销量预测 | ★ |

**常用思维框架**

| 框架 | 说明 | 频率 |
| --- | --- | --- |
| 拆解树 / MECE 原则 | 把问题拆成「不重不漏」的小问题，如销售额 = 流量 × 转化率 × 客单价 | ★★★ |
| 指标体系 / 指标树 | 从北极星指标向下拆出过程指标 | ★★★ |
| 假设驱动 | 先提出可能原因，再用数据逐个验证，而不是盲目翻数据 | ★★★ |
| 金字塔原理 | 结论先行，以上统下，归类分组，逻辑递进 | ★★★ |
| 5W2H | What、Why、Who、When、Where、How、How much，梳理需求用 | ★★ |
| AARRR（海盗模型） | 获取、激活、留存、变现、传播，产品增长常用 | ★★ |
| 人货场 | 零售、电商分析的基本视角 | ★★ |
| 用户生命周期 | 引入期、成长期、成熟期、衰退期，对应不同运营策略 | ★★ |
| SWOT / 4P / 波士顿矩阵 | 偏商业分析的通用框架 | ★ |

**三类最高频的分析题套路**

1. **指标异动怎么分析**（如日活突然下降 10%）
   1. 先核实数据本身：口径是否变化、数据是否漏采、是否有统计故障。
   2. 确认是真实变化后，判断是持续性还是一次性，是整体还是局部。
   3. 按维度拆解：渠道、地区、版本、设备、新老用户。
   4. 结合内外部因素：产品改版、活动、节假日、竞品、政策、技术故障。
   5. 给出结论、影响评估和建议动作。
2. **如何评估某次活动效果**：明确目标，确定评估指标，选对照基准（同期未参与用户或历史同期），计算增量，扣除成本算投入产出，最后给出是否复用的建议。
3. **如何设计 / 定义一个指标**：先问业务目标，再定义口径（分子、分母、时间、范围），说明优缺点，补充配套的护栏指标。

## 7. 数据可视化

**图表选择**

| 想表达什么 | 推荐图表 | 备注 |
| --- | --- | --- |
| 趋势 | 折线图 | 时间在横轴 |
| 对比 | 柱状图、条形图 | 类别名长用条形图；柱状图纵轴从 0 开始 |
| 占比 | 堆叠柱、环形图、饼图 | 类别不超过 5 个，否则改用条形图 |
| 分布 | 直方图、箱线图 | 看形状和异常值 |
| 相关 | 散点图 | 可加趋势线 |
| 流程转化 | 漏斗图 | 注意每步基数 |
| 排名 | 排序后的条形图 | 取 TopN |
| 地域 | 地图 | 非必要不用 |
| 构成变化 | 堆叠面积图 | 看结构随时间变化 |

**可视化原则（★★★）：**

1. 一张图只讲一件事，标题直接写结论，如「4 月新用户次日留存下降 5 个百分点」，而不是「留存分析」。
2. 去掉多余装饰：网格线、3D 效果、花哨渐变。
3. 颜色克制，用一种颜色突出重点。
4. 坐标轴不要随意截断，避免误导。
5. 图要配数据标注和单位。

**看板设计（★★）：** 最上方放核心指标，其下放趋势，再往下放维度拆解；每个指标都有口径说明；筛选器放在顶部；不要堆太多图。

## 8. 业务理解

只会工具的分析师很容易产出「正确但没用」的结论。业务理解不是天生的，要刻意练。

| 内容 | 说明 | 频率 |
| --- | --- | --- |
| 行业核心指标 | 进入一个行业前，先搞清它靠什么赚钱、核心指标是什么 | ★★★ |
| 业务流程 | 能画出用户从接触到付费的完整路径，每一步对应哪些数据 | ★★★ |
| 产品基础 | 理解功能、用户路径、版本迭代与数据的关系 | ★★ |
| 财务基础 | 收入、成本、利润、毛利，能看懂简单的经营数据 | ★★ |
| 运营基础 | 拉新、促活、留存、转化、召回的常见手段 | ★★ |
| 与业务方沟通 | 听懂需求背后的真实目的，而不是只执行字面需求 | ★★★ |

**不同行业的核心指标举例**

| 行业 | 常看指标 |
| --- | --- |
| 电商 | GMV、订单数、客单价、转化率、复购率、退货率、库存周转 |
| 游戏 | 新增、日活、留存、付费率、ARPPU、LTV、渠道 ROI |
| 内容 / 短视频 | 日活、人均时长、完播率、互动率、创作者留存 |
| 教育 | 线索量、试听转化、续费率、完课率 |
| SaaS / 企业服务 | 付费客户数、ARR、续约率、流失率、获客成本 |
| 金融 | 放款量、逾期率、获客成本、风险指标 |

**接需求时可以问的五个问题：** 这个分析要支持什么决策？谁会看？用来做什么？期望什么时候要？数据口径和范围有没有要求？

## 9. 沟通与表达

| 知识点 | 说明 | 频率 |
| --- | --- | --- |
| 结论先行 | 开头就说结论和建议，再给证据 | ★★★ |
| 分析报告结构 | 背景与目的 → 方法与口径 → 主要发现 → 结论 → 建议 → 风险与下一步 | ★★★ |
| 一页纸汇报 | 能用一页说清核心结论，领导通常没时间读长文 | ★★★ |
| 数据故事化 | 用一条逻辑主线串起数据，而不是罗列图表 | ★★ |
| 针对不同对象调整 | 对领导讲结论与影响，对业务讲动作，对技术讲口径与细节 | ★★ |
| 日报 / 周报 / 专题报告 | 常规产出的三种形式 | ★★ |
| 说清不确定性 | 明确哪些结论有把握，哪些是推测，数据的局限在哪 | ★★ |
| 推动落地 | 分析的价值在于有人据此行动，要跟进结果并复盘 | ★★ |

## 10. 常见分析误区

新人最容易踩，面试官也爱问，建议逐条对照自查。

| 误区 | 说明 | 频率 |
| --- | --- | --- |
| 把相关当因果 | 冰淇淋销量和溺水人数同升，原因是天气，不是互为因果 | ★★★ |
| 幸存者偏差 | 只分析留下来的用户，忽略已经流失的 | ★★★ |
| 辛普森悖论 | 分组看与合并看结论相反，必须按维度拆开 | ★★★ |
| 平均数陷阱 | 均值被极端值拉高，要同时看中位数和分布 | ★★★ |
| 口径不一致 | 对比的两个数字统计规则不同 | ★★★ |
| 基数效应 | 基数很小时，百分比变化看起来很夸张 | ★★★ |
| 样本太小或不具代表性 | 结论不稳定或不能推广 | ★★★ |
| 只看总量不看结构 | 总量没变，内部结构可能已大变 | ★★ |
| 时间窗口选择偏差 | 刻意选对结论有利的时间段 | ★★ |
| 过度解读 | 对随机波动编故事 | ★★ |
| p-hacking / 多重比较 | 看很多指标，挑显著的写结论 | ★★ |
| 先射箭后画靶 | 先有结论再找数据支撑 | ★★ |
| 图表误导 | 截断坐标轴、不一致的刻度、不当的 3D | ★★ |
| 只描述不建议 | 报告罗列现象，没有落到行动 | ★★★ |

## 11. 求职相关

**招聘中常见的考察环节**

| 环节 | 考察内容 |
| --- | --- |
| 简历筛选 | 项目经历、工具技能、是否贴合 JD |
| SQL 笔试 | 取数能力，多是业务场景题，如留存、连续登录、TopN |
| Excel / 数据处理笔试 | 透视表、函数、清洗 |
| 业务分析题 | 指标异动、活动评估、指标设计 |
| 统计与实验题 | 假设检验、A/B 测试、概念辨析 |
| 项目深挖 | 追问「为什么这样分析」「结论是什么」「带来什么影响」 |
| 行为与沟通面试 | 沟通、抗压、学习能力、稳定性 |

**项目作品集的写法（★★★）**

1. 先写业务问题，如「哪类游戏更受玩家欢迎，价格与评价有关吗」。
2. 说明数据来源、口径和清洗过程。
3. 展示分析方法与关键发现。
4. 给出结论与建议，并说明局限。
5. 每个技术点、每个结论，你都要能讲清原理和依据；讲不清的内容不要写进简历。

**高频面试题示例**

- 次日留存率怎么算？如果下降了怎么分析？
- 同比和环比的区别？分别适合什么场景？
- 均值和中位数有什么区别，什么时候用哪个？
- 如何评估一次促销活动的效果？
- 设计一个 A/B 测试需要考虑哪些要素？
- 数据里有异常值，怎么处理？
- 平均客单价上升，是好事吗？（要拆结构）
- 你的项目里为什么选这个指标？结论是否可靠？

## 12. 学习路线与优先级

时间因人而异，下面以先后顺序给出，并非固定周期。

**阶段 1：打地基（先做）**

- Excel 核心函数与数据透视表。
- SQL 全部 ★★★ 内容（见 SQL 手册）。
- 本手册第 1 节的核心指标与业务概念。

**阶段 2：建立分析能力**

- 基础统计：均值、中位数、分布、相关、假设检验的基本含义。
- 第 4 节的分析方法和思维框架，每周练几道业务分析题。
- 一个 BI 工具（Tableau 或 Power BI 或 FineBI，按目标岗位选）。
- 第 7 节可视化原则。

**阶段 3：拉开差距**

- Python pandas 数据处理。
- A/B 测试的完整逻辑。
- 第 10 节分析误区，拿自己的项目逐条对照。
- 沟通表达：练习写一页纸的分析总结。

**阶段 4：求职化**

- 做 1 到 2 个能讲清楚的分析项目，带业务问题和结论。
- 整理简历，每个技能点都能被追问。
- 模拟面试：SQL 题、业务分析题、统计概念题各练几轮。

**必须强调的三点：**

1. 不必全部学完再投简历，达到阶段 2 的基础就可以开始投，边投边补。
2. 优先级永远是：★★★ 全部掌握 → ★★ 有所了解 → ★ 遇到再查。
3. AI 工具能帮你写 SQL 和代码，但选什么指标、怎么拆问题、结论可不可信，需要你自己判断，这部分才是长期竞争力。

## 13. 术语速查表

| 术语 | 一句话解释 |
| --- | --- |
| 维度 | 用来分组或筛选的角度，如时间、地区、渠道 |
| 度量 | 可以计算的数值，如金额、次数、人数 |
| 颗粒度 | 一行数据的详细程度 |
| 口径 | 指标的统计规则 |
| 基数 | 作为分母或比较基准的数量 |
| 同期群（Cohort） | 按相同特征或时间进入的一批用户 |
| 北极星指标 | 最能代表产品核心价值的指标 |
| 埋点 | 在产品中记录用户行为的数据采集方式 |
| 看板 | 把核心指标集中展示的页面 |
| 归因 | 判断结果该归功于哪些因素 |
| 增量 | 因某项动作而额外带来的结果，剔除自然增长 |
| 基线 | 用来对比的参照水平 |
| 护栏指标 | 防止优化一个指标时伤害别的指标 |
| 样本偏差 | 样本不能代表整体 |
| 置信区间 | 估计值的可能范围 |
| p 值 | 衡量差异是否可能只是随机波动 |
| 长尾 | 少数头部占大量份额，多数个体份额很小的分布 |
| 冷启动 | 新用户、新产品缺少数据时的状态 |
| 画像 | 对用户特征的结构化描述 |
| ETL | 抽取、转换、加载，数据进入仓库的过程 |
